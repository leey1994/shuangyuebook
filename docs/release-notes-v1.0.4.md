## 爽阅 V1.0.4

**切章不再干等、能换字体了，导入上千条书源也不卡。**（覆盖安装即可升级，书架、书源、进度、缓存、听书音频全部保留）

这版是三个方向一起走：把「阅读 3.0」书源当脚本执行的能力补齐一大截；治好"有时候翻下一章要等很久"；再把字体、书源列表、低端机流畅度这三块做了一遍。

---

### 一、字体：不用再忍受系统默认的那一款

* **应用不再内置任何字体文件** —— 安装包体积一点没涨（里面的字体文件只有图标字体）
* **三款可选**：思源宋体（衬线，接近纸书印刷体）、思源黑体（无衬线，屏幕清晰）、霞鹜文楷（手写楷体，有笔锋），外加"跟随系统"
* **点了才下载**：选中的那款才开始下（约 8~13 MB），面板里能看到实时百分比，下完自动切换生效
* **下完就归你**：字体存在本机，清理阅读缓存不会删它，之后断网也能正常显示
* **进书即预热**：上次选的字体会在你打开书时后台悄悄下好，不用干等
* **网络不稳也不慌**：内置多个下载线路轮换，失败会明确提示并自动回到系统字体，不会把正在看的字弄乱
* 入口在**阅读器「排版」页**和**「我的 → 阅读 → 阅读字体」**，两处是同一个面板

### 二、切章不再干等

* **同一章只抓一次**：后台正在预取第 N+1 章时你正好翻到第 N+1 章，以前是两边各发一个请求互相拖；现在前台直接搭上预取那趟车，一次网络请求两边共用
* **前后翻章不再抓网**：最近读过的 8 章正文留在内存里，翻回去、来回跳转是瞬开的（磁盘缓存仍照旧，冷启动不受影响）
* **预取学会让路**：你在读的章节正在取正文时，后台预取先停下等（最多 4 秒），慢慢一章一章补，不再和前台抢同一个站点的限速
* **慢源自动收敛**：WebView 渲染型的源（一章要渲染好几秒）只预取一章就收手，几十章的请求不会把隐藏浏览器队列占满
* **滚动模式提前备粮**：离章末还有约一屏半（1200px）就开始抓下一章，滑到底时正文通常已经在了
* **开卷时的一份礼让**：进书时的后台目录刷新延后 0.6 秒，避免它和正文请求、预取三个一起挤

### 三、导入 1000 多条书源不再卡

* **列表只画看得见的那几行**：以前 1000 条书源每一帧全部重画一遍，现在只画屏幕上的十几行，滑起来跟几十条一样顺
* **搜索框**：顶部放大镜图标，可按名称 / 地址 / 分组查找，另有"仅看已启用"开关；输入有防抖，连续打字不会每敲一下就重排一遍
* **打开/关闭书源不再全表重算**：以前每点一次开关都要把上千条重新算一遍，现在只动你点的那一条
* **批量启用 / 批量删除**：一次操作只通知一次、只写一次盘，不再几百次重复
* **导入和导出不卡界面**：1000 条书源的 JSON 解析与打包挪到后台线程做，导入完界面立刻就响应
* **启动更快**：开机读那 1000 条书源也改成后台解析，首页出来得快得多
* **进度提示不再排队**：以前导入时会有一条接一条地滑进屏幕几百次，现在只留最新一条

### 四、低端机上"运行起来也卡"

* **桌宠不再每帧重画整屏**：待机时的呼吸起伏交给画笔自己画，只有走路、眨眼才重建界面；切到后台、系统开了"减少动画"、或你关掉桌宠时，动画直接停表（省电也省 CPU）。顺带修了"眼睛偶尔不眨"的问题
* **阅读页脚的时间不再拖着整页重画**：以前每秒刷新一次时间会把整页正文重建一遍，现在只改那一行字
* **封面图加了隔离层**：列表滚动时不再顺带把封面重画一遍
* **改一条书源不再重建上千个对象**：适配器按地址复用，只重建真正变了的那一条
* **开机流程瘦身**：磁盘缓存、阅读统计、书源体检这些不着急的事挪到界面出来之后再做

### 五、书源 · 脚本执行能力（对齐「阅读 3.0」）

* **发现页支持 JS 形态的 `exploreUrl`**：脚本里 `list.push({title, url})` 生成的分栏能用，`infoMap`（分栏选择器）也接上了，选择结果会记住
* **发现页分类可异步补全**：脚本里再联网取分类的源不再只出半截列表
* **jsoup 节点树导航**：`children()` / `parent()` / `nextElementSibling()` / `previousElementSibling()` / `ownText()` 这些成员可用（很多源的目录、正文脚本靠它们遍历）
* **`java.*` 接口补齐**：`java.getElement(s)` / `java.setContent` / 字节数组与交互类成员，脚本里按原版写法调不会静默失败
* **加密链路**：`Packages.java` 系的两处致命缺陷修掉，`createSymmetricCrypto`、字节数组、登录态（`@loginInfo` / `@loginHeader`）与 `book` 变量都能用
* **WebView 链路打通**：`java.webView`、章网址尾缀里的 `{"webView":true}` 会真的开隐藏浏览器渲染，正文靠页面 JS 注入的源（塔读这类）能取到字了
* **`data:` URI 本地响应**：脚本里 `java.ajax("data:...")` 直接拿到内容，不再当网络请求发出去
* **文本伪类**：`:contains()` / `:containsOwn()` 可用（`#list dt:contains(正文) ~ dd a` 这种写法现在能命中）
* **兄弟组合子**：CSS 的 `~` / `+` 与 jsoup 伪类能共存，以前整条选择器会报错退化成空结果

### 六、书源 · 目录与字段规则

* **顺序前缀 `-` / `+`**：目录规则里 `-` 反序、`+` 正序按原版语义生效
* **字符串上下文里的子规则**：条目本身是 HTML 片段时（`a@text`、`a@href` 这类）按片段解析，不再整页串味
* **补网脚本被吞的问题**：JS 里 `try { java.ajax(...) } catch` 抛出的"挂起"不再被 catch 吞掉，目录 112 章只出 1 章的源恢复正常
* **请求头容错**：书源 Cookie 里带中文占位（`其他你抓到的Cookie`）以前直接抛"无效请求头"，整条源不可用；现在按 RFC 只保留可见 ASCII，能请求就请求，站点该拦就拦
* 修复部分源"目录只剩 1 章""正文只有一句"的问题；发现页/搜索里 `@Json:`、`@XPath:` 大写前缀不再静默失效

### 安卓安装包怎么选

V1.0.3 起按架构分包，按你的手机选一个装即可：

| 你的设备 | 选这个 | 体积 |
| - | - | - |
| 2016 年后的手机（绝大多数） | `ShuangYue-v1.0.4-arm64-v8a.apk` | 约 25 MB |
| 很老的 32 位机型（装不上 / 提示"应用未安装"时） | `ShuangYue-v1.0.4-armeabi-v7a.apk` | 约 23 MB |
| Windows 电脑 | `ShuangYue-v1.0.4-windows-x64.zip` | 约 18 MB |

两个 APK 同包名同签名，可互相覆盖安装，数据不丢。Windows 包解压后双击 `novel_reader.exe`（务必解压到新建的空文件夹）。
