## 爽阅 V1.0.4

**切章不再干等，书源脚本跑得更像原版。**（覆盖安装即可升级，书架、书源、进度、缓存、听书音频全部保留）

这版两条主线：一是把「阅读 3.0」书源当脚本执行的能力补齐一大截（发现页 JS、jsoup 节点树、`java.*` 接口、加密链路、WebView 链路），二是治好了"有时候翻下一章要等很久"。

### 速度 · 切章不再干等

* **同一章只抓一次**：后台正在预取第 N+1 章时你翻到第 N+1 章，以前是两边各发一个请求互相拖；现在前台直接搭上预取那趟车，一次网络请求两边共用
* **前后翻章不再抓网**：最近读过的 8 章正文留在内存里，翻回去、来回跳转是瞬开的（磁盘缓存仍照旧，冷启动不受影响）
* **预取学会让路**：你在读的章节正在取正文时，后台预取先停下等（最多 4 秒），慢慢一章一章补，不再和前台抢同一个站点的限速
* **慢源自动收敛**：WebView 渲染型的源（一章要渲染好几秒）只预取一章就收手，几十章的请求不会把隐藏浏览器队列占满
* **滚动模式提前备粮**：离章末还有约一屏半（1200px）就开始抓下一章，滑到底时正文通常已经在了
* **开卷时的一份礼让**：进书时的后台目录刷新延后 0.6 秒，避免它和正文请求、预取三个一起挤

### 书源 · 脚本执行能力（对齐「阅读 3.0」）

* **发现页支持 JS 形态的 `exploreUrl`**：脚本里 `list.push({title, url})` 生成的分栏能用，`infoMap`（分栏选择器）也接上了，选择结果会记住
* **发现页分类可异步补全**：脚本里再联网取分类的源不再只出半截列表
* **jsoup 节点树导航**：`children()` / `parent()` / `nextElementSibling()` / `previousElementSibling()` / `ownText()` 这些成员可用（很多源的目录、正文脚本靠它们遍历）
* **`java.*` 接口补齐**：`java.getElement(s)` / `java.setContent` / 字节数组与交互类成员，脚本里按原版写法调不会静默失败
* **加密链路**：`Packages.java` 系的两处致命缺陷修掉，`createSymmetricCrypto`、字节数组、登录态（`@loginInfo` / `@loginHeader`）与 `book` 变量都能用
* **WebView 链路打通**：`java.webView`、章网址尾缀里的 `{"webView":true}` 会真的开隐藏浏览器渲染，正文靠页面 JS 注入的源（塔读这类）能取到字了
* **`data:` URI 本地响应**：脚本里 `java.ajax("data:...")` 直接拿到内容，不再当网络请求发出去
* **文本伪类**：`:contains()` / `:containsOwn()` 可用（`#list dt:contains(正文) ~ dd a` 这种写法现在能命中）
* **兄弟组合子**：CSS 的 `~` / `+` 与 jsoup 伪类能共存，以前整条选择器会报错退化成空结果

### 书源 · 目录与字段规则

* **顺序前缀 `-` / `+`**：目录规则里 `-` 反序、`+` 正序按原版语义生效
* **字符串上下文里的子规则**：条目本身是 HTML 片段时（`a@text`、`a@href` 这类）按片段解析，不再整页串味
* **补网脚本被吞的问题**：JS 里 `try { java.ajax(...) } catch` 抛出的"挂起"不再被 catch 吞掉，目录 112 章只出 1 章的源恢复正常
* **请求头容错**：书源 Cookie 里带中文占位（`其他你抓到的Cookie`）以前直接抛"无效请求头"，整条源不可用；现在按 RFC 只保留可见 ASCII，能请求就请求，站点该拦就拦

### 修复

* 部分源「目录只剩 1 章」「正文只有一句」——分别对应字符串上下文子规则、补网被吞、正文多段取值三处
* 发现页/搜索里 `@Json:`、`@XPath:` 大写前缀不再静默失效
