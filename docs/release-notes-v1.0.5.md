# 爽阅 v1.0.5 更新说明

版本号：**1.0.5+11**（versionCode：arm64 = 2011 / armeabi-v7a = 1011 / x86_64 = 4011）
上一版：1.0.4+10

## 一、字体设置：应用不再内置字体，选中才下载

用户反馈想要「能换字体」。这版把字体做成了**按需下载**：

- **安装包不内置任何字体文件**（没有 .ttf/.otf 塞进 assets），装包大小不变。
- 阅读器「排版」页新增 **「字体」** 一行；「我的 → 阅读 → 阅读字体」也能进同一���面板。
- 面板里三款可选：**思源宋体**（衬线，接近纸书印刷体）、**思源黑体**（无衬线，屏幕清晰）、**霞鹜文楷**（手写楷体，有笔锋），外加「系统默认」。
- 流程是「**点了才下载**」：选中的那款才开始下载（约 8~13 MB），面板里显示实时百分比，下完自动切换并生效。
- 下载走**多镜像容错**（jsDelivr 主站 + fastly 备用），断网/超时会给明确提示，不会把当前字体改坏。
- 字体文件存在**应用支持目录**，清理「阅读缓存」不会删掉它；下次打开直接用，断网也能用。
- 进阅读器时会**自动预热**上次选的字体（后台下载），下载期间正文先用系统字体显示，不会白屏等字。
- 字体名加了 `sy_` 前缀，避免和系统里同名字体（用户自己装过思源宋体）撞车。

下载失败、文件损坏（头字节校验）都会自动回退到系统字体，不影响阅读。

## 二、导入 1000+ 条书源不再卡

用户反馈「导入一千多条书源软件很卡」。这版把书源这条链路整体重做了一遍：

| 原来 | 现在 |
| --- | --- |
| 书源管理页用 `ListView(children: [...])`，1000 条**每帧全部构建** | 改成 `SliverList.builder`，只构建可视区域 |
| `sources` getter 每次访问都复制整张表（一帧里取好几次） | 稳定实例的缓存视图，没变更时零拷贝 |
| 每行按 url 反查用 `indexWhere`（1000 行 = O(n²)） | `Map<String,int>` 索引，O(1) |
| 批量启用/删除 = N 次通知 + N 次写盘 | 合并成 1 次通知 + 1 次落盘 |
| 导入 1000 条 JSON 在主线程解析（界面僵住） | 解析挪到后台 isolate，界面不卡 |
| 导出 1000 条 JSON 在主线程编码 | 编码同样挪到后台 isolate |
| 启动时读 1000 条书源在主线程解码 | 启动读盘也走后台 isolate |
| 导入时进度提示排队滑入几百条 | 只保留最新一条 |

另外给书源管理页加了**搜索**：顶部放大镜图标，支持按名称 / 地址 / 分组匹配，另有「仅看已启用」开关。搜索有 260ms 防抖 + 结果缓存，连续输入不再每键重建列表。

## 三、低端机上「运行起来也卡」

这版集中处理了会持续掉帧的几处：

- **桌宠动画**：原来待机时每一帧都 `setState`，等于每帧重建整棵子树。现在呼吸起伏交给画笔自己重绘；走路/眨眼才重建。切到后台、系统开了「减少动画」、或关掉桌宠时，动画**直接停表**（省 CPU 和电）。顺带修了眨眼偶发不眨的问题。
- **阅读器页脚时间**：原来每秒 `setState` 一次，等于每秒重建整页正文。现在只有那一行时间单独刷新。
- **封面图**：加了重绘边界，列表滚动时不再连带重画封面。
- **书源登记表**：改一条书源不再重建上千个适配器对象（按 url 复用）。
- **启动速度**：磁盘缓存、阅读统计、书源体检这些「不急着做」的事挪到首帧之后，首帧前只保留书源与脚本变量。
- 封面解码、缩略图尺寸处理保持原有的 `cacheWidth` 限制（避免大图解码把内存打爆）。
