> 测试时间：2026-10-16 ｜ 样本：5 个公开合集抽样 392 条 ｜ 全链路真实网络测试 + 离线解析实证

> 实证：`tool/legado_parse_case_test.dart`（真实 HTML + 真实规则，离线复现）

## 一、结论摘要

**兼容性现状：差，且大头不在引擎。** 抽样的 208 条「阅读 3.0 格式」文本书中：

| 指标 | 数量 | 占比 |
| --- | --- | --- |
| 总数（3.0 文本源） | 208 | 100% |
| ├ 无 searchUrl（探索页/按钮型，搜索天然不存在） | 45 | 21.6% |
| ├ 搜索靠 JS 构建（@js / `<js>`，需 JS 引擎） | 35 | 16.8% |
| └ 明文 URL（引擎真正能试的） | 128 | 61.5% |
| &nbsp;&nbsp;&nbsp;&nbsp;├ 搜索成功 | 12 | 9.4%（占明文） |
| &nbsp;&nbsp;&nbsp;&nbsp;└ 其中目录成功 → 正文成功 | 5 → **2** | **全链路 1.0%** |

另有 **107 条是「阅读 2.0」老格式**（AlyLeaf 整包，扁平 `ruleSearchUrl` 键）——导入 3.0 引擎后等同于「没有搜索入口」，全部不可用。

**"为啥会这样"三层答案：**

1. **生态层（主因，≈50% 失败源头）**：公开合集里近一半源根本没有 HTTP 可渲染的搜索入口（探索页型/JS 按钮型/老格式）；大辉狼自己的校验器都判 39% 无效（5541 → 有效 3373）。任何纯采集客户端都吃不下这半边。
2. **引擎层（可修，实锤 3 个）**：① POST 请求缺 `Content-Type: application/x-www-form-urlencoded` → PHP 站收不到搜索词 → 静默 0 结果（抖音/速读谷实证）；② CSS4 `:has()` 不支持 → bookList 直接 0 命中（抖音实证）；③ `@js:` 关键字段（bookUrl/bookList）→ 整行被静默丢弃 → 用户看到"搜不到书"（若雨中文：100 行解析成功、全被丢光）。
3. **站点层**：60 条硬错误中 52 条是网络/站方（TLS 重置 24、CF 403 7、超时 7、404 死站 6…）；另有站点改版导致规则过期（伪速读谷实证）。

修复 P0 两项（POST 头 + 失败显式化）后，预计本样本通过率可从 ~4% 提到 ~10-15% 量级；受生态上限约束，导入书源应保持「补充」定位。

### 判定方法

- 探针直接调用 App 的真实代码路径（`BookSource` → `LegadoSource` → `OnlineRepo`/`OnlineBookService`），走真实网络；

- 对关键失败案例，另存真实响应 HTML 做**离线解析复现**（不依赖网络，结论可复核）。

## 四、三个实锤案例（可离线复现）

### 案例 1：若雨中文 —— `@js:` bookUrl → 整行静默丢弃

- 站点响应：HTTP 200 / 59KB，结果表格完整（`table_01`、`tbody` 齐全）；
- 离线跑引擎 `parseSearchPage`：bookList 命中 **100 行**，首行书名「斗破苍穹」正常取出；
- 但 `ruleSearch.bookUrl` 是 `@js:...`（`select('td').get(1).select('a').attr('href').replace(...)`，逻辑极简单）；
- 结果：**100 行全部被丢弃 → 0 本**（`online_repo.dart` 里"没有书籍页地址的条目点开必炸"→ `continue`）；
- 同一站点手写原生适配器完全可用。用户感知 = "这个源搜不到书"。

### 案例 2：抖音小说 —— 两个缺陷叠加

- 请求层：python 用表单头 POST → 结果页 16KB，关键词出现 **22 次**；用 `text/plain`（模拟引擎现状）→ 关键词出现 **0 次**（服务器没收到搜索词）；
- 解析层：bookList `.novelslist2 ul li:has(a)` → 命中 **0**；`ul li` → 命中 **21**（`:has()` 是 CSS4，package:html/csslib 不支持）；
- 两层都断，各自独立。

### 案例 3：伪速读谷（sudugu.cc）—— 有效响应 + 规则过期

- python 表单头 POST → 130KB 有效结果页（含搜索结果）；
- 但源规则 `.itemtxt h3 a@text` 在该页命中 **0** → 该源规则写的不是现版页面结构（规则过期，或对应的是站点另一套模板）；
- 同站手写原生适配器（走 GET + GBK/双编码还原）完全可用。

### 旁证：篱笆好文学「三胞胎」

同一个站点，三份源三种命运：`/sou?wd={{key}}` 版搜索成功（n=11）；`search.php@post->keyword={{key}}` 版（**旧版 @post 语法**，引擎解析不了 → 请求打到假 URL）；`search.php` 另一版 empty。**成败完全取决于规则写法与引擎方言支持度。**

## 五、引擎修复优先级（按性价比）

| 优先级 | 项目 | 成本 | 收益 |
| --- | --- | --- | --- |
| **P0** | POST 无显式 content-type 时默认补 `application/x-www-form-urlencoded`；`charset` 选项同时用于请求体编码 | ≈10-20 行 | 13 条空结果 + 23 条 POST 错误的主要修复面 |
| **P0** | 静默失败显式化：bookUrl/bookList 解析失败时保留条目并附原因（或健康检查标注「该源依赖 JS」） | ≈20 行 | 把"搜不到"黑洞变成可诊断提示（用户价值最大） |
| P1 | 剥离 `<js>…</js>` 前置块（后随明文 URL 且无变量引用时直接用） | ≈15 行 | 3 条直接受益（最终小说网等），减少 JS 误判 |
| P1 | `:has()` 常见形态预处理（`sel:has(tag)` → 先选 sel 再按含 tag 过滤） | ≈30-50 行 | 抖音系书源；或评估替换 CSS 引擎 |
| P2 | `@post->` / `@get->` 旧语法转译成 `,{...}` 形式 | ≈20-30 行 | 老源，本批 1-2 条 |
| P2 | 阅读 2.0 老格式（`ruleSearchUrl` 一族）导入时明确拒收提示 | ≈10 行 | 消灭"导入成功但全不可用"的困惑 |
| ✗ | 自研 JS 引擎（Rhino 级） | 无底洞 | 不建议；如需，评估 quickjs FFI（体积/性能/安全代价另议） |

**上限预期**：即使全部修完，无 JS 引擎前提下本样本通过率上限约 15-25%（48%→21.6% 无入口 + 老格式 + 死站构成生态硬顶）。导入书源保持「补充替代站点」定位，内置手写原生源为主线 —— 与 v1.0.0 的 9+4 决策一致。

## 六、局限与复现

### 局限

- 关键词固定（斗破苍穹/凡人修仙传），个别站可能真的没有这两本书 → 「站点侧空结果」占比可能略高估；
- 单轮测试、无重试：慢站/限流站（如全本小说网的目录失败）复测结果可能有变化；
- 网络判定基于本机（中国大陆直连）：TLS 重置类 24 条在不同网络/代理下结果会变；
- 本机为 Windows：内容阶段的隐藏 WebView 兜底不可用（本批 webView 源 0 条，无实际影响）；
- 样本为公开合集抽样（非"最优质源清单"），已按域限额防止单站刷屏。

### 复现

```bash
# 1) 批量探针（真实网络，392 条约 70 秒）
flutter test tool/legado_compat_probe_test.dart -r expanded \
  --dart-define=SRC=<sample_all.json> --dart-define=OUT=<results.jsonl>

# 2) 离线解析实证（三案例，秒级）
flutter test tool/legado_parse_case_test.dart -r expanded
```

完整样本与响应存档：`%TEMP%\opencode\legado_batch\`（`sample_all.json`、`html\` 含 4 份真实响应、`probe_sites.py` 站点侧实证脚本）；本仓库仅留档 `sources/legado-compat-results.jsonl`（392 条逐源结果）。
